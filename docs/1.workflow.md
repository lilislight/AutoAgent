# Workflow 基础定义

本文只定义 Workflow 的静态结构。Runtime、Scheduler、恢复以及具体执行策略不在本文中定义。

## 最小 Python 伪代码

```python
Workflow:
    id: str
    version: str
    nodes: list[Node]
    edges: list[Edge]
    sub_workflows: list[SubWorkflow]

SubWorkflow:
    id: str
    workflow: Workflow                 # 编译时展开，仅用于结构复用

Node:
    id: str
    executable: Callable | Operator | Capability | Workflow

    input_mapping: InputMapping | None = None
    output_binding: OutputBinding | None = None

    execution_mode: Literal["await", "spawn"] = "await"
    map: Map | None = None
    stream: Stream | None = None

Edge:
    id: str
    source: str                        # Source Node id
    target: str                        # Target Node id
    on: Literal["complete", "error"] = "complete"
    condition: Condition | None = None

Operator:
    id: str
    implementation: Callable
    input_type: type[TypedDict] | type[BaseModel] | None
    output_type: type[TypedDict] | type[BaseModel] | None

Capability:
    id: str
    operators: list[Operator]

Map:
    aggregate: MapAggregation | None = None
    max_parallelism: int | None = None

Stream:
    reducer: StreamReducer
```

## Workflow

Workflow 是一份静态图定义，由 Node、Edge 和可选的 SubWorkflow 组成。它不保存 Invocation 状态、执行结果、Task Handle 或 Runtime Context。

Workflow 可以有多个结构入口和多个结构出口：

- 没有入边的 Node 是入口；
- 没有出边的 Node 是出口；
- 一次 Invocation 从一个指定入口进入；
- Invocation 的结果由实际到达的出口确定。

## SubWorkflow

SubWorkflow 只用于编译时结构复用。编译后，其内部 Node 和 Edge 展开到父 Workflow，并与父 Workflow 共享同一个 Invocation 和 Runtime Context。

SubWorkflow 不持有独立的执行模式、Map、Stream 或其他运行语义；这些语义全部定义在其内部 Node 上。父 Workflow 的 Edge 最终仍然连接展开后的 Node id。

作为独立子任务执行的 Workflow 不使用 SubWorkflow，而是作为 Node 的 `executable`。

## Node

Node 是 Workflow 中的静态执行位置。`executable` 可以是：

- `Callable`：直接可调用对象；
- `Operator`：具体可执行模块；
- `Capability`：一组候选 Operator 的能力抽象；
- `Workflow`：创建独立 Child Invocation 的 Workflow。

### Input Mapping

Input Mapping 根据当前 Node 收到的数据构造 `executable` 的输入。单入边和多入边 Node 都可以设置 Input Mapping。

没有 Input Mapping 时：

- 入口 Node 使用 Invocation Input；
- 恰好一个输入时，直接使用该输入；
- 多个输入不进行隐式合并，必须设置 Input Mapping。

普通 Node 的 Input Mapping 返回一次 executable 输入：

```python
InputMapping(...) -> ExecutableInput
```

Map Node 的 Input Mapping 返回有限、有序的输入列表：

```python
InputMapping(...) -> list[ExecutableInput]
```

Input Mapping 可以读取当前输入、Invocation Input 以及只读 Runtime Context。前置 Node 的业务结果通过当前入边传递，不通过全局 Node Output 查询。

### Output Binding

Output Binding 在 Node 得到最终逻辑输出后，将需要保留的数据绑定到 Runtime Context。它属于 Node 静态定义，但 Context 的提交与冲突处理由 Runtime 定义。

### Child Workflow 执行模式

`execution_mode` 只在 `executable` 为 Workflow 时生效：

```python
execution_mode: Literal["await", "spawn"] = "await"
```

| 模式 | 含义 | Node 逻辑输出 |
|---|---|---|
| `"await"` | 创建 Child Invocation 并等待其完成 | Child Invocation 的结果 |
| `"spawn"` | 创建 Child Invocation 后立即返回 | Child Invocation 的 Task Handle |

其他 executable 默认在当前 Invocation 中执行并等待结果。

### Map

Map 是 Node 的一级执行语义，不是 NodePolicy。它表示在一个 Node 执行中，对有限、有序的输入列表多次执行同一个 executable。

```text
list[ExecutableInput]
        -> executable × N
        -> list[ExecutableOutput]
        -> optional aggregate
        -> NodeOutput
```

相同输入的重复执行同样使用 Map，由 Input Mapping 直接构造重复输入：

```python
InputMapping(...) -> [same_input, same_input, same_input]
```

没有 `aggregate` 时，Node 输出按照输入顺序组成 `list[ExecutableOutput]`；设置 `aggregate` 时，其返回值成为 Node 的最终逻辑输出。

`max_parallelism` 限制同一个 Map Node 同时运行的 executable 调用数量；`None` 表示不在 Node 定义中设置并行上限。

Map 内部的多次 executable 调用不产生多个 Node，也不分别判断普通出边。

### Stream

Stream 是 Node 的一级执行语义，不是 NodePolicy。它表示一次 executable 调用产生多个 Chunk，并由 StreamReducer 归约为一个 executable 输出。

```text
Iterator[Chunk]
        -> StreamReducer.add(Chunk) × N
        -> StreamReducer.finish()
        -> ExecutableOutput
```

Stream 可以与 Map 组合。每个 Map 输入分别完成自己的 Stream Reduction，随后再进行 Map Aggregation：

```text
Map item 0: Chunk* -> ExecutableOutput 0
Map item 1: Chunk* -> ExecutableOutput 1
Map item 2: Chunk* -> ExecutableOutput 2
                              -> Map Aggregation
                              -> NodeOutput
```

## Edge

Edge 是 Node 之间的静态有向连接，同时表达控制依赖和数据流向。

```python
Edge:
    source: str
    target: str
    on: Literal["complete", "error"] = "complete"
    condition: Condition | None = None
```

### Complete Edge

`on="complete"` 消费 Source Node 的成功完成状态，向 Target Node 传递 Source Node 的最终逻辑输出。

```python
Edge(source="search", target="process", on="complete")
```

### Error Edge

`on="error"` 消费 Source Node 的最终失败状态。

```python
Edge(source="search", target="handle_error", on="error")
```

### Condition

Condition 决定与当前 Source Node 状态匹配的 Edge 是否被选中：

- Complete Edge 的 Condition 可以读取 Source Node Output；
- Error Edge 的 Condition 可以读取 Source Node Error；
- 两者都只能读取只读 Runtime Context；
- Condition 不修改 Context，也不读取任意历史 Node Output。

未设置 Condition 时，与 Source Node 最终状态匹配的 Edge 默认被选中。多个匹配的出边可以同时被选中。

## Operator 与 Capability

Operator 是最基础的具体可执行模块。Capability 是一组候选 Operator 的能力抽象；实际执行最终落到一个具体 Operator。

### Operator 输入输出契约

Operator 必须显式声明输入与输出类型，只支持：

- `TypedDict`；
- 受限的 Pydantic `BaseModel`；
- `None`，表示没有输入或没有输出。

```python
Operator:
    input_type: type[TypedDict] | type[BaseModel] | None
    output_type: type[TypedDict] | type[BaseModel] | None

    implementation: (input_type) -> output_type
```

Operator 最多接收一个业务输入对象。多个业务字段必须定义在同一个 `TypedDict` 或 `BaseModel` 中，不能展开为多个函数参数。

Operator 的输入输出必须能够转换为框架规定的持久化数据格式，并在恢复时重新验证。不能作为输入输出的类型包括 Callable、Iterator、协程、Task、文件句柄、连接以及任意用户对象。

Pydantic Model 只能使用框架支持的持久化字段类型，不允许 `arbitrary_types_allowed` 或任意自定义对象。`TypedDict` 同样需要在每次 Operator 调用前后进行运行时验证，不能只依赖静态类型检查。

### 契约匹配

Operator 契约不做结构兼容：即使两个类型具有完全相同的字段，只要不是同一个声明类型，也不能直接视为兼容。

```python
class SearchOutput(TypedDict):
    items: list[str]

class RankInput(TypedDict):
    items: list[str]

# 字段结构相同，但 SearchOutput 与 RankInput 不是同一个契约。
```

Node 或 Edge 直接传递数据时，Source Output 与 Target Input 必须使用同一个声明类型。需要改变类型或字段结构时，必须通过显式 Input Mapping 完成转换，并由 Runtime 按 Target Input 类型验证结果。
