# 步骤 8：多 Session group commit 实验

## 结论

本轮完成配置实验，保留 `AUTOAGENT_DURABLE_BATCH_DELAY_MS=0`，未修改产品 Writer、持久化确认语义或默认设置。0 ms 已能合并同时就绪的不同 Session Event；额外等待 1/5 ms 没有带来足以覆盖单 Session 代价的稳定收益。

这是定向初筛及复核，不是步骤 9 的完整验收。小幅并发差异不能解释为稳定加速。默认策略未改变，因此本轮没有新增可计入累计收益的产品优化。

## 测试方法

- 同一份冻结的完整 V2 Python 包，Artifact 8192 bytes，durable；内存监控关闭，队列与缓存预算保持默认。源码和工具 SHA256 见 provenance.json，依赖见 environment.json。
- 原生 Server 独立进程，HTTP `/api/v2/executions` 创建独立 Session，`/__bench/wait` 调用既有 `Host.join()`，随后 flush 捕获当时的 accepted frontier，再读 durable SQL 输出。每个请求不等待全局排空；整轮结束后检查全局队列为零及 accepted == durable。
- Chain 包含 entry、10 个 work Node 和 finish，业务负载 16 KiB，无外部 LLM。并发 1/8/32，分别完成 5/16/32 次调用；每进程额外预热一次，不计入测量次数。32 并发是一波有限请求，不能当作稳态吞吐或长时公平性结论。
- 比较 0/1/5 ms，每配置三个独立 Server/数据库进程；各轮配置顺序轮换，后端顺序交替。正常延迟与 SQL 诊断分开，后者每配置一次，不混入下表。
- 三轮正常组 54 次 Server、954 次正式调用；独立诊断 18 次 Server、318 次调用。共 72 次完整 Server、1272 次调用，输出摘要和规范事实/投影行数配平，最终持久化屏障均通过。
- 共享主机，没有独占 CPU 或 cgroup 隔离；RSS 仅为 Server 进程，未归因 PostgreSQL 共享进程/WAL。只有 Chain 定向实验，未重跑六场景、V1/B0 或一小时负载。

## 观察路径的独立问题

最初通过 `Host.wait_execution()` 观察终态。SQLite 0 ms 的单进程探索中，8 个并发 Session、16 次调用耗时 37.13 秒；同源码 `join` 首轮为 5.54 秒。它们是等待方式不同的探索结果，不能混入 group commit A/B 或既有步骤累计收益。

32 并发观察组由本轮主动中止：进程运行 236.4 秒、Server CPU 230.2 秒，控制器尚未消费到一个完整结果。SIGINT 后线程池等待在途 HTTP，随后终止本轮临时 SQLite Server 释放等待；exit -9 是人工终止，不是 OOM kill、自动超时或完成样本。原始 result、memory 和 server log 保留在忽略目录。此组不进入成功延迟/吞吐汇总。

已完成的观察路径探索共 6 次 Server、63 次调用；随后两个后端各补一组 8 并发 SQL 诊断，增加 2 次 Server、32 次调用。加上主实验共 80 次完成 Server、1367 次正式调用，另有 1 次主动中止；预热均不计入。

源码中 `wait_execution()` 保留 100 ms 兜底并重查 `execution_state()`；并发等待者会放大数据库查询和 accepted overlay 重建。上述诊断用于确认这一负载差异，不能把全部时差精确归因到某一函数。修复应另行评估通知覆盖、Runtime 中断、buffered accepted 状态与外部提交契约，不能简单删除兜底。本轮未修改该查询策略。

## 验证与复现

初次定向回归 135 项中，一个 SQLite 取消观察测试失败：Writer 已注册订阅，但调用线程尚未收到 token 就被取消，原清理范围未覆盖该窗口。新测试在冻结旧包上让两个后端都确定复现失败；随后只修复 DatabaseSink 的订阅清理：屏蔽注册任务的外层取消，并在 finally 取得 token 后注销。四项新旧取消测试通过。此修复不改变 Writer、COMMIT 或默认等待设置。

主实验与观察诊断的全部数字来自修复前冻结包；主实验的 Host.join 路径不调用 execution_notifications，因此不将取消修复计为 group commit 性能收益。最新产品相对冻结包仅这一文件有差异，SHA256 和失败/复核记录见 cancellation-fix.json、verification.json。高并发观察查询问题仍未修复。
